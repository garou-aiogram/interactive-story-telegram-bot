# Story Bot

Telegram-бот, который ведёт интерактивные истории на локальной GGUF-модели.
Языки: английский, русский, испанский — выбираются при `/start`.

Модель нигде не зашита в код. Меняешь путь к `.gguf` в скрипте запуска
`llama-server` — бот работает дальше без единой правки.

## Архитектура

```
Telegram  ──►  bot (aiogram3)  ──HTTP──►  llama-server  ──►  model.gguf
                    │
                    └──► SQLite (языки, истории, ходы, summary)
```

Два независимых процесса. Бот не знает, какая модель крутится — он видит
только OpenAI-совместимый эндпоинт.

## Запуск

### 1. Инференс

Собери llama.cpp, положи GGUF, укажи путь в `run_llama_server.sh`
(или `.ps1` на Windows) и запусти:

```bash
./run_llama_server.sh
```

Проверка: `curl http://127.0.0.1:8080/v1/models`

### 2. Бот

```bash
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt

cp .env.example .env           # впиши BOT_TOKEN
python -m bot.main
```

## Настройка нагрузки

`--ctx-size` делится между слотами: `--ctx-size 32768 --parallel 4`
даёт 8k контекста на пользователя.

`MAX_CONCURRENT` в `.env` должен быть **не больше** `--parallel`.
Если больше — запросы копятся внутри сервера и ловят таймаут.

Прикидка VRAM: вес модели + примерно `ctx_size × parallel` KV-кэша.
`--cache-type-k q8_0 --cache-type-v q8_0` режет кэш примерно вдвое.

## Управление контекстом

Интерактивная история — это отправка всей предыдущей переписки на каждом ходу.
Чтобы не выбить окно контекста:

- последние `KEEP_RECENT_TURNS` ходов уходят дословно;
- всё, что раньше, сворачивается отдельным вызовом модели в сжатые заметки
  (персонажи, места, предметы, незакрытые линии) и хранится в `stories.summary`;
- сжатие идёт фоновой задачей и не задерживает ответ игроку.

Пороги настраиваются в `.env`.

## Команды

| Команда | Что делает |
|---|---|
| `/start` | выбор языка при первом заходе |
| `/new` | новая история, спросит завязку (`/skip` — придумает сам) |
| `/end` | закрыть текущую историю |
| `/lang` | сменить язык |
| `/help` | как это работает |

Любой обычный текст = следующий ход игрока.

## Продакшн

В `deploy/` лежат два systemd-юнита. Правь пути, потом:

```bash
sudo cp deploy/*.service /etc/systemd/system/
sudo systemctl enable --now llama-server story-bot
journalctl -u story-bot -f
```

`llama-server` держи на `127.0.0.1`. Наружу его выставлять не надо — у него нет
нормальной аутентификации, открытый порт превратится в чужой бесплатный GPU.

## Что стоит доделать под свою задачу

- рейт-лимит по пользователю (сейчас есть только блокировка параллельных генераций);
- фильтрация ввода/вывода, если бот публичный;
- бэкап SQLite (`.db`, `.db-wal`, `.db-shm` — все три файла).
